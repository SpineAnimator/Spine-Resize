## .skel — бинарный рантайм

Формат как в Esoteric `SkeletonBinary` 4.2/4.3 (`spine-runtimes`).

Проверено на `gunslinger.skel` (30283 байт):

- чтение: version `4.3.26`, 70 костей, 70 слотов, 1 скин, анимации cherry / gunslinger, 69 region/mesh
- кости совпали с JSON (hip x=61.19174 y=-357.3628, spine rotation=83.02865, length=202.5142, …)
- **запись с factor=1 раньше расходилась**: 3288 отличающихся байт, первый на offset 24041, повторное чтение падало
- причина: `writeCurves` писал curve-byte и bezier **до** следующего ключа. В файле порядок другой (как `readTimeline` в рантайме):

```
time0, values0,
time1, values1, curve0, [bezier floats],
time2, values2, curve1, [bezier],
… последний ключ без curve
```

- после правки `writeCurves`: **roundtrip diffs = 0**, повторное чтение ок
- шкуры до анимаций и так совпадали (граница skins = 23792). Ломалась только запись костных таймлайнов
- слоты, события, ik/transform/path/physics/slider/deform/drawOrder пишутся сырыми байтами. Масштаб по ним ещё не проставлен, кроме костных translate/scale/shear/rotate, которые разобраны в `Flt` с флагом `k`

Масштаб расстояний: у `Flt` поле `k=1` (x/y/length костей, вершины, width/height region). `scaleSkel()` умножает такие float и сбрасывает `k`. `writeSkel(sk, factor)` умеет умножать при записи, если `k` ещё 1. Нельзя вызывать оба сразу — будет двойной масштаб.

Bake scale=1 для .skel ещё не сделан (в JSON он есть в `applyScale`). Иерархия родителей в .skel уже читается: `bone.parent` — индекс.

AABB для .skel ещё не посчитан в UI. Для JSON на gunslinger setup-pose примерно **1645×1603**. В цель 300 это множитель около **0.18**.

## .spine — файл редактора

`symbols.spine` (23353 байт) — это **сырой deflate** (zlib wbits=-15) всего файла с нулевого байта.

- энтропия исходника ~7.99
- после inflate: **60511** байт
- версия внутри: MSB-строка `4.3.26` (не 4.3.2: последний символ с битом 0x80)
- обратно в редактор: сжать тем же raw deflate и подменить файл. Обычный zlib-заголовок `78 9c` не использовать

### Строки

Строка без длины: байты ASCII, **у последнего байта выставлен бит 0x80**, символ = `byte & 0x7F`.

Пример: `hip` = `68 69 F0` (`p`|0x80). `gunslinger` заканчивается на `F2` (`r`|0x80).

### Кости (setup)

71 раз встречается подпись сразу после имени:

`21 3F 80 00 00 02 01 1E`

Это не только кости: сюда же попадают вложения вроде `Ch_cherry`. Имена с этой подписью в порядке файла начинаются так:

`root`, `hand-left-control`, `gunslinger`, `hip`, `spine`, `tors`, `hand_left`, …

Перед именем (тег + big-endian float32) стабильный хвост:

| тег | смысл на кости | масштабировать? |
|-----|----------------|-----------------|
| `0A` + f32 | local x | да |
| `0B` + f32 | local y | да |
| `09` + f32 | length | да |
| `0C` + f32 | rotation | нет |
| `0E` + f32 | scale (часто 1, у Ch_frame_light scaleY=7.228224) | нет, это множитель |
| `0D` + f32 | часто 1.0 | нет, пока не доказано |
| `22 00 00 00 00` | константа между x и scale | не трогать |
| `17 00 00 00 00` | перед `1C` | не трогать |
| `1C 13` или `1C 18` | тип записи (18 чаще у control) | не parent |
| `1B 15 1D 00` / у root `1B 01 01 1D 00` | маркер перед y | не parent |

Проверено на hip: x `42 74 C4 58` = 61.19174 сразу после `0A`, y `C3 B2 AE 70` = -357.36 после `0B`.

Родитель **не найден** как один байт-индекс. Равномерный масштаб всех local x/y/length всё равно масштабирует мир, даже без дерева: вклад каждой трансляции линейный. Для bake чужого scale≠1 дерево нужно, его пока нет.

### Вложения (регион)

Вокруг `Ch_cherry` (width 204, height 195, x≈4.035, y≈4.782), смещения в распакованном файле ~11820:

| тег | значение | пример |
|-----|----------|--------|
| `0C` + f32 | **height** (в кости тот же тег = rotation) | 195 |
| `07` + f32 | attachment y | 4.782 |
| `06` + f32 | attachment x | 4.035 |
| `08` + f32 | 1.0 | не масштаб дистанции |
| `09` + f32 | 1.0 на вложении, на кости это length | нельзя слепо масштабировать все `09` |
| `0B` + f32 | **width** (на кости тот же тег = y) | 204 |

Одинаковые теги в кости и во вложении значат разное. Глобально умножать все `0A/0B/0C` нельзя: `0C` повернёт кости.

Как отличать:

- кость: после имени `21 3F 80 00 00 02 01 1E`, дистанции это ближайшие `0A` (x), `0B` (y), `09` (length)
- регион: после имени часто `21 01 …`, в окне перед именем `06`=x, `07`=y, `0B`=width, `0C`=height

Ширины/высоты по файлу также встречаются с тегами `10` (width, ~55 штук) и `11` (height). Это уже другой контекст (меши). Слепое умножение всех `10/11` не проверено.

### Меши и анимации .spine

- вершины меша (пример Ch_frame_light: 69, -17, 2.06) лежат массивом, не как тег `0A` на каждую
- translate-ключи JSON (104 штуки) лежат парой BE-float. Паттерн `00 + x + y + 01` находится 149 раз — близко, но с запасом, вслепую лучше не масштабировать
- deform-ключей в этом JSON нет

### Оценка кадра

Грубый AABB JSON (регионы в setup, с поворотом кости):

- min (-791, -924), max (854, 679)
- размер **1645 × 1603**
- в квадрат 300: factor ≈ min(300/1645, 300/1603) ≈ **0.182**

## Что делать следующим коммитом

1. В `app.js` провести `.skel` через `readSkel` → AABB по костям и region → `scaleSkel` **или** `writeSkel` с одним factor, не оба.
2. Bake scale для .skel: свой scaleX умножить на local x и length, scaleY на local y, затем записать 1. Родитель уже есть.
3. Деформации анимации .skel: сейчас сырые байты, translate костей масштабируется через curves. Deform-вершины надо пометить `k=1` или патчить float на местах.
4. `.spine`: inflate, масштабировать только поля в распознанных записях костей (`0A/0B/09`) и регионов (`06/07/0B/0C` в контексте вложения), deflate raw, отдать файл. Проверить, что Spine редактор открывает результат.
5. Картинки и atlas масштабировать тем же factor, что и скелет.
6. UI: чёрный, без прокрутки страницы, мало текста. Кнопка одна.

## Как гонять проверку .skel

Из корня репозитория (Node 22):

```bash
node --experimental-strip-types -e '
import { readFileSync } from "fs";
import { readSkel, writeSkel } from "./src/lib/spineSkel.ts";
const b = new Uint8Array(readFileSync("recovered-spine/gunslinger.skel"));
const out = writeSkel(readSkel(b), 1);
let d=0; for (let i=0;i<b.length;i++) if (out[i]!==b[i]) d++;
console.log(d===0 ? "roundtrip ok" : "DIFF "+d);
'
```

Ожидание: `roundtrip ok`.
