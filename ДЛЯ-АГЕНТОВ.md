# Для следующего агента

Дата проверки: 2026-10-09. Репозиторий: `SpineAnimator/Spine-Resize`, ветка `main`.
Сайт: https://spineanimator.github.io/Spine-Resize/ — GitHub Pages с корня `main`. Пуш в `main` и есть деплой.

Токен GitHub в репозиторий не класть. Файлы крутятся только в браузере. `.skel` не переписывать, пока `writeSkel(readSkel(bytes), 1)` не даёт 0 отличий.

Образцы: `recovered-spine/gunslinger.json`, `gunslinger.skel`, `symbols.spine`.

Пользователь открывал результат в Spine 4.3.26 и прислал:

- `symbols.json` → `ZipException: invalid distance too far back` и «The file appears to be JSON, not a Spine project file».
- `symbols.spine` → «The project footer is missing», project version 4.3.26, та же `ZipException`.
- В JSON «анимации не нашлись, их пропустило». `.skel` ломать нельзя.

Ниже только то, что прогнано в этой сессии. Редактор Spine здесь не запускался: проверялись Node, Python zlib и Java 17 `Inflater(true)` / `Deflater(6, true)`.

## 1. Что такое .spine

`symbols.spine` — 23353 байта. Это один raw deflate (zlib wbits = -15) и хвост 20 байт. Обычный zlib (`78 9c`) и gzip не подходят.

```
payload 23333 байта  +  footer 20 байт
00 00 00 00
00 00 5B 25          длина сжатого потока, big-endian (23333)
F2 7F 94 00 B5 AF 5F CF
02 0B 02 0B          магия, последние 4 байта
```

Java 17 на исходном файле: `finished=true`, `totalIn=23333`, `remaining=20`, распаковано 60511 байт.

`Deflater(6, nowrap=true)` на этих 60511 байтах совпал с исходным сжатым телом байт в байт.
То же самое даёт Python `zlib.compressobj(level=6, wbits=-15, memLevel=8, strategy=Z_DEFAULT_STRATEGY)`.

Pako level 6 даёт другой поток (23414 байт, не равен исходному). Java `Inflater(true)` его всё равно дочитывает до `finished` и оставляет 20 байт футера, если длину в футере переписать. Ломает не «чужой» deflate, а одно из двух:

- футера нет;
- в футере длина больше реального потока, и inflater съедает футер как сжатые данные. Отсюда сразу оба текста: `invalid distance too far back` и `The project footer is missing`.

Текущий `scaleSpineFile` футер сохраняет и длину пишет в байты 4..7. Проверка на выходе ресайза (target 300, bake, center, factor ×0.136): файл 23609 байт, Java `finished=true`, `totalIn=23589`, хвост 20 байт, магия на месте. Это не значит, что редактор Spine примет файл: 8 байт `F2 7F 94 00 B5 AF 5F CF` не равны crc32/adler32 ни сжатого, ни распакованного тела. Их смысл не доказан. Пока их копируют как есть.

Старая заметка в `НАХОДКИ.md` ошиблась в версии. В начале распакованного файла лежит `4.3.26`, не `4.3.2`. Байт `B6` — это символ `6` с битом конца строки (`B6 & 7F = 36`). Поэтому редактор и пишет `Project version: 4.3.26`.

## 2. Ошибка на symbols.json — это не битый JSON

Путь из лога: `/Users/imac/Data/Animation/json|atlas|png2/symbols.json`.

Spine при Open / Import Project всегда сначала делает inflate. Обычный JSON не deflate, inflater кидает `invalid distance too far back`, затем редактор пишет: «The file appears to be JSON, not a Spine project file». Тот же текст будет на любом честном экспорте JSON. Это не доказательство, что ресайзер сломал JSON.

JSON в редактор кладут через Import Data, не через Open. Анимации из JSON в уже открытый скелет Spine сам не подтягивает: нужен проект `.spine` или импорт как новый скелет.

## 3. JSON-анимации текущий код не выкидывает

`gunslinger.json`, Spine export 4.3.26, ключи: `skeleton`, `bones`, `slots`, `constraints`, `skins`, `animations`.

До ресайза и после (`resizeEntries`, target 300, bake, center):

| | до | после |
|---|---|---|
| анимации | `cherry`, `gunslinger` | те же |
| ключей таймлайнов | 282 | 282 |
| IK constraints | neck, plash1, plash2, stropa1, stropa2, hand-right, hand-left | те же, кости на месте |

Пример кривой: `cherry` / `Ch_frame_light` translate `x = 262.9868` стал `35.863` (×0.136). Масштабируются `cy` безьера, не время. `deform.offset` не трогается: это индекс вершины, из-за него Spine пропускает ключ.

`hash` из `skeleton` удаляется. `referenceScale` не масштабировать.

Строка статуса считает анимации json и skel вместе: на паре файлов получается «4 anim» при двух клипах. Это счётчик, не потеря данных.

## 4. .skel не сломан

`writeSkel(readSkel(gunslinger.skel), 1)` → 0 отличий, 30283 байта.

После того же ресайза файл снова читается: 70 костей, анимации `cherry` и `gunslinger`.

`scaleSkel` уже умножает поля с `k=1`. Повторный `writeSkel(sk, factor)` умножит второй раз. Так не вызывать.

Bake: свой scale кости не двигает её x/y. Он уходит в length, детей и вложения. Неравномерный scale (`Ch_frame_light` scaleY 7.23) честно в scaleX/scaleY без shear не кладётся.

## 5. Почему в .spine «нет анимаций»

В конце распакованного проекта нет вложенного zlib. Там ссылки, не сами клипы:

```
importDataFile
./cherry.json
/Users/imac/Data/Animation/gunslinger.json
importDataFolder
./cherry.json
/Users/imac/Data/Animation/gunslinger.json
./images/
./audio
```

Редактор подгружает анимации из этих путей. Если рядом нет `cherry.json` / `gunslinger.json`, клипы пустые. Абсолютный путь `/Users/imac/Data/Animation/gunslinger.json` жив только на той машине.

Внутри бинаря ключи translate есть, но шаблон легко врёт.

Точные байты float32 из JSON совпадают только у 17 пар из 53: остальные отличаются округлением. С допуском 0.05 находятся все 53 ненулевые пары x,y. Перед каждой стоит `01 01` и float времени. Пример: `neck-control` около смещения 13945.

Это не разрешение умножать каждый `01 01`. На `symbols.spine` такой шаблон встречается 480 раз, сотни из них — нули в костях и мешах. Старый фильтр портил соседние float или пропускал настоящие ключи. `animPairs = 0` оставлен нарочно. Пока нет якоря, который оставляет только эти 53 пары, таймлайны `.spine` не масштабировать. Значение из JSON вроде `262.9868` в проекте лежит с другим округлением, его не удаляли.

Предупреждения редактора `Constraint deleted: ik hand-right / plash1 / …` и `IK constraint not found … animation gunslinger` совпадают с импортом анимации в скелет, где этих IK уже нет. В исходном JSON все семь IK ссылаются на существующие кости. Ресайзер их не удаляет.

## 6. Что уже делает код и чего не делать

- `src/lib/spine/spineProject.ts` — inflate, масштаб костей (`0A` x, `0B` y, `09` length), регионов и мешей по якорям, raw deflate, футер 20 байт. factor 1 возвращает исходные байты. Поворот и scale костей помечены locked.

- Родителя кости в `.spine` нет. Bake scale для `.spine` не делать.

## 7. Что проверять перед пушем

```bash
node --experimental-strip-types -e '
import { readFileSync } from "fs";
import { readSkel, writeSkel } from "./src/lib/spine/spineSkel.ts";
const b = new Uint8Array(readFileSync("recovered-spine/gunslinger.skel"));
const out = writeSkel(readSkel(b), 1);
let d=0; for (let i=0;i<b.length;i++) if (out[i]!==b[i]) d++;
console.log(d===0 ? "roundtrip ok" : "DIFF "+d, b.length);
'
```

Ожидание: `roundtrip ok 30283`.

Для `.spine` после любой правки: Java `Inflater(true)` на целом файле обязан закончиться (`finished`) и оставить хвост, у которого последние 4 байта `02 0b 02 0b`, а big-endian u32 по смещению 4 равен числу сжатых байт.

JSON: имена `cherry` и `gunslinger` на месте, ключей не меньше, чем было, `deform.offset` не умножен.

## 8. Куда копать дальше

1. Не открывать JSON как проект. В статус сайта писать прямо: `.json` — это Import Data, `.spine` — Open.
2. Во внешние пути `importDataFile` / `importDataFolder` не лезть шаблоном float: это строки. Если ресайз кладёт JSON рядом, пути `./cherry.json` и `./gunslinger.json` должны остаться целыми.
3. Масштаб translate в `.spine` не включать, пока шаблон не отсекает 480 ложных `01 01` и не оставляет проверенные пары. Допуск по float обязателен: точные байты JSON совпадают только у 17 из 53. Проверка: factor 1 → те же распакованные байты; factor ≠ 1 → Java inflate `finished` и 20 байт футера. `.skel` на этом не трогать.
4. Восемь байт футера перед магией. Пока не доказано, что редактор сверяет их с телом. Если Spine продолжит ругаться на футер при живом inflater — смотреть их.
5. Не коммитить `node_modules`, токен, чужие zip из `attachments`.
