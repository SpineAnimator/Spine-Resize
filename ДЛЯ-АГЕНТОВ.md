## 1. Что такое .spine

`symbols.spine` — 23353 байта. Это один raw deflate (zlib wbits = -15) и хвост 20 байт. Обычный zlib (`78 9c`) и gzip не подходят.

```
payload 23333 байта  +  footer 20 байт
00 00 00 00
00 00 5B 25          длина сжатого потока, big-endian (23333)
F2 7F 94 00 B5 AF 5F CF
02 0B 02 0B          магия, последние 4 байта
```

Java 17 на исходном файле: `finished=true`, `totalIn=23333`, `remaining=20`, распаковано 60511 байт.

`Deflater(6, nowrap=true)` на этих 60511 байтах совпал с исходным сжатым телом байт в байт.
То же самое даёт Python `zlib.compressobj(level=6, wbits=-15, memLevel=8, strategy=Z_DEFAULT_STRATEGY)`.

Pako level 6 даёт другой поток (23414 байт, не равен исходному). Java `Inflater(true)` его всё равно дочитывает до `finished` и оставляет 20 байт футера, если длину в футере переписать. Ломает не «чужой» deflate, а одно из двух:

- футера нет;
- в футере длина больше реального потока, и inflater съедает футер как сжатые данные. Отсюда сразу оба текста: `invalid distance too far back` и `The project footer is missing`.

Текущий `scaleSpineFile` футер сохраняет и длину пишет в байты 4..7. Проверка на выходе ресайза (target 300, bake, center, factor ×0.136): файл 23609 байт, Java `finished=true`, `totalIn=23589`, хвост 20 байт, магия на месте. Это не значит, что редактор Spine примет файл: 8 байт `F2 7F 94 00 B5 AF 5F CF` не равны crc32/adler32 ни сжатого, ни распакованного тела. Их смысл не доказан. Пока их копируют как есть.

Старая заметка в `НАХОДКИ.md` ошиблась в версии. В начале распакованного файла лежит `4.3.26`, не `4.3.2`. Байт `B6` — это символ `6` с битом конца строки (`B6 & 7F = 36`). Поэтому редактор и пишет `Project version: 4.3.26`.

## 8. Куда копать дальше

1. Не открывать JSON как проект. В статус сайта писать прямо: `.json` — это Import Data, `.spine` — Open.

5. Не коммитить `node_modules`, токен, чужие zip из `attachments`.


## 9. Якорь translate в .spine

Дата: 2026-10-09. Файл `recovered-spine/symbols.spine`, распаковка `zlib.decompress(raw[:-20], -15)` → 60511 байт. Сверка с `gunslinger.json`, анимации `cherry` и `gunslinger`. Редактор Spine не запускался. С §10 этот обход стоит в `spineProject.ts` и в `app.js`.

Прежние «53 пары» — это поиск ненулевых x,y с допуском. Он занижал. Структурный обход находит все ключи.

### Заголовок таймлайна

Шесть байт сразу перед первым ключом:

```
84 01 01 <type> 01 <count>
```

| type | что это | значений после time |
|---|---|---|
| `00` | rotate | 1 float, угол, не масштаб |
| `01` | translate | x, y — дистанции |
| `02` | scale | x, y — множители, часто 1. Не умножать как дистанцию |

`<count>` — один байт, число ключей. В этом файле максимум 9. Больше 127 не встречалось: вдруг дальше varint, не проверено. Байт `01` между type и count стоит у всех костных таймлайнов этого файла.

Сколько заголовков в `symbols.spine` и сколько таймлайнов в JSON:

| | проект | JSON |
|---|---|---|
| translate `84 01 01 01 01` | 38 заголовков, 109 ключей | 35 таймлайнов, 104 ключа |
| rotate `84 01 01 00 01` | 28 | 27 / 70 ключей |
| scale `84 01 01 02 01` | 7 | 3 / 10 ключей |

Все 35 JSON-translate легли на заголовок. Три лишних в проекте тоже настоящие записи, их нет в экспорте JSON:

- смещение 12465, 2 ключа, первый time=1 кадр, x=0, y=0
- смещение 12658, 2 ключа, первый time=15, x=0, y=0
- смещение 12890, 1 ключ, time=0, x=0.5, y=-3.5

Их надо масштабировать вместе с остальными. Это не те 480/1080 ложных `01 01`.

### Ключ

Сразу за заголовком идёт `count` ключей. Каждый начинается с `85 01 01`. Таких подписей в файле 307: те же байты у rotate и scale. Тип берётся из заголовка, не из подписи ключа.

```
85 01 01
time   float32 BE     секунды * 30, не секунды
x      float32 BE
y      float32 BE
```

15 байт. `skeleton.fps` в JSON нет, у редактора по умолчанию 30, и это сходится на каждом ключе: 1.6333333 с → 49.0, 0.8666667 с → 26.0, 2.333333 с → 70.0, 0.5 с → 15.0.

Между ключом и следующим (у последнего ключа хвоста нет):

- один байт `00` — без блока кривой, расстояние между началами ключей 16 (таких промежутков 16);
- 41 байт, первый `01` — блок кривой, расстояние 56 (таких 55).

Других длин между 71 не-последним ключом этих 38 таймлайнов нет. Если длина другая — весь таймлайн пропустить, не патчить наполовину.

Все 104 ключа JSON совпали по time×30, x, y с допуском 0.08. Точные байты float из JSON по-прежнему совпадают только у части пар: обход по заголовку допуск для поиска не использует.

### Блок кривой

41 байт после значений ключа, если до следующего `85 01 01` ровно 56 байт от начала ключа. Иначе между ключами один байт `00` и кривой нет. Первый байт блока бывает `01` (54 раза) или `00` (1 раз у `symbols.spine`). Дальше 10 float32 BE, по 5 на ось x и на ось y. Пятый float оси в этом файле всегда 0. Если он не 0, ось не трогать.

`2^31` — байты `4F 00 00 00`, сторож, не дистанция.

| вид | 5 float оси | сколько осей | что умножать |
|---|---|---|---|
| partial | сторож, сторож, время, значение, 0 | 32 блока, обе оси | только 4-й float |
| full | время, значение, время, значение, 0 | 22 блока, обе оси | 2-й и 4-й |
| shifted | время, значение, сторож, сторож, 0 | 1 блок, обе оси | только 2-й |

Время не умножать. Сторож не умножать.

Примеры:

- `cherry` / `Ch_frame_light`, time 0.5, bezier `[0.6666667, 0, 0.8333333, 262.9868, …]`. В блоке время=20.0 (`0.6666667*30`), значение=0. Второго якоря (25.0 и 262.9868) нет: сторож, ручка по умолчанию на следующий ключ.
- `card-a2`: время=23.3333, значение равно собственному x/y ключа. cx2/cy2 из JSON в блоке нет.
- Вид кривой в JSON не равен блоку в проекте. `card-a` в JSON bezier, в проекте один байт `00`. `card-f2` в JSON linear, в проекте 41 байт с живыми числами (6.99, −52.51, …). Для ресайза правда — `.spine`, не экспорт.
- stepped у `finger-left` и `gun-zatvor` кладёт x/y ключа в слоты значений (вид full). Их надо умножать вместе с ключом.

### Как обходить, чтобы не повторить порчу соседних чисел

```
найти 84 01 01 01 01 <count>     count от 1 до 64
следующие 3 байта обязаны быть 85 01 01
для каждого ключа кроме последнего:
    после 15 байт ключа либо
        00 и сразу 85 01 01          (промежуток 16, кривой нет)
        либо через 41 байт 85 01 01  (промежуток 56, блок кривой)
    иначе весь таймлайн пропустить, ничего в нём не множить
умножить x (+7) и y (+11)
в блоке кривой умножить только слоты значений из таблицы выше
```

Один таймлайн из пяти ключей имеет блок на 41 байт, который начинается с `00`, а не с `01`. Проверка «байт 00 значит один байт линейности» ломает обход. Сначала смотреть, не стоит ли `85 01 01` сразу после этого `00`. Иначе читать блок 41 байт.

Нельзя умножать каждый `85 01 01` (их 307). Нельзя умножать scale (type `02`) и rotate (type `00`). Bake для `.spine` по-прежнему нельзя: индекс родителя не найден. `spineSkel.ts` этим путём не ходит.

Надпись на сайте: не «Spine», а «Spine Resize Skeleton». Это `<title>` и `<h1>` в `index.html`. `app.js` заголовок не переписывает. Правка только `.ts` на GitHub Pages не видна: тот же код должен лежать в `app.js`.
